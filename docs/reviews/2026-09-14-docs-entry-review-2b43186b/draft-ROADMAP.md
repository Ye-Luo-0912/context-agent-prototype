# 后端主体路线

本文只定义能力阶段、边界和退出条件，不维护工单进度、CI run 或“今天先做谁”。当前事实见 [CURRENT.md](CURRENT.md)，唯一执行队列见 [NEXT_TASKS.md](NEXT_TASKS.md)。

## 本阶段交付：可持续完成任务的后端

沿用一个 RuntimeActor、Core 权限/effect 权威、可替换 ContextEngine 和公共平台契约。支持任务接收与中途纠正、证据搜索和范围读取、工具执行、验证、中断、冷恢复及可核验交付。

界面不是这些能力的前置条件；先通过已有 headless/host/SDK 验收。客户端后续仍使用相同公共契约，不复制任务状态或编排逻辑。

## 三条协作线

| 主线 | 拥有的工作 | 需要交付的行为 |
|---|---|---|
| 执行核心与工具（A） | 回合、任务、工具/进程与验证接缝 | 能推进、能停止、能恢复，模型能看见真实工具结果 |
| 上下文/GC/搜索（B） | 工作集、冷热迁移、查回、存储保护 | 当前证据准确可见，退出工作集后仍可找回，未知所有权不被删除 |
| 平台/供应商 KV（C） | 公共入口、配置、Provider 缓存接线与账目 | 非 GUI 客户端可驱动完整流程，缓存配置到达实际端点，费用不被虚报 |

共享 contracts/command/compose 由一个集成人维护；按明确接口需求协作，不以三个近似结构代替同一个事实。

## 退出条件

后端实际旅程能走完，必要风险有对应验证，相关实现进入目标源码并通过既有 CI。记录每项证据的 SHA、环境和作用范围。

源码存在、正式入口接通、默认启用、脚本化旅程通过、真实模型质量、供应商命中与费用收益，分别报告；一种证据不外推成另一种。

明确当前支持的资源规模及预算。先实现有界、可恢复、可解释的版本，不宣称无限历史稳定；不要等待 GC/缓存理论最优才交付主体。

## 后续选择

主体旅程完成后，依据真实使用瓶颈选择一项：冷元数据驻留控制、搜索减少重复轮次、稳定证据阶段布局或压缩/缓存经济性。算法研究须有明确任务和对照，不由旧报告自动触发。

GUI 的恢复扩展由后续用户目标决定，不与本阶段后端收尾绑定。历史 M15/M16/M17 的路线、阶段编号和实验窗口属于证据，不再在本页充当“当前开工顺序”。
