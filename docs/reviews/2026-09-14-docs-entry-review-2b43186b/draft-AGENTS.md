# Coding Agent 开发约定

## 工作入口

先遵循当前用户明确要求，再读 `docs/CURRENT.md` 的有效范围和 `docs/NEXT_TASKS.md` 中本次选定的任务。两份文件之外的历史报告不自动产生任务。稳定规则留在本文件；阶段、负责人、进度、CI run 和实施额度不在本文件重复维护。

开工先核对 `git status --short`、当前分支和 HEAD，阅读相关差异。文档所述本地实现不代表 main 已包含；main 缺少某实现，也不代表共享工作树没有它。不要覆盖、重置、清理、私自暂存或提交他人的未提交改动。

围绕选定任务读取生产代码、直接调用方、相关契约和必要测试。源码检索先限定 `crates/`、`clients/`、`apps/` 或 `scripts/`；只有调查历史依据时才进入 `docs/reviews/`、归档和冻结实验快照。不得把搜索结果里的旧代码副本当作当前实现。

## 必须保持的边界

- RuntimeActor 是唯一任务/回合编排者；沿用 TaskAnchor、ExecutionState、Checkpoint、RuntimeHandle，不另建任务真相或并行调度权威。
- Core 保持审批、权限、effect 身份、提交和恢复权威。ToolSpec、模型输出、缓存命中、恢复记录都不是授权。
- ContextEngine 可替换；工具不能绕过接口私读或修改记忆存储；外部正文、路径和工具观察不能提升为 system 指令。
- 工作集退出、可逆外置和存储删除分别处理。语义终态不被热度或 lease 复活；必要证据的版本、范围、完整性和引用保护不因降本放宽。
- 不确定的副作用不能自动重放。取消请求不是清理完成；恢复/枚举未完成不是空集；计划勾选不是可信验证。
- 默认 OperatorClosureOnly 下，普通 final 不等于持久任务完成；`next_action` 也不自动成为完成阻塞项。
- 客户端使用公共契约和类型化事实，不从显示文字猜审批、完成或恢复；不向远端导出 CorePort、恢复半事务或全部 RuntimeCommand。
- 保持 crate 依赖方向、conformance 和既有 CI。共享 contracts、command、compose 接口由集成人统一收口，不在共享工作树互相覆盖。

## 如何交付

每个工作分支聚焦一个可验收切片，先说明用户动作或实际故障，再完成实现及其生产接线，补必要回归。若任务涉及源码审查，明确完整读取、局部读取、静态推导和已执行验证的区别。

文档改动做文档检查；代码改动先做受影响模块的定向检查，合入按既有 CI 执行。高风险恢复/权限/副作用问题需要对应行为验证；不为普通改动重跑冻结付费实验，不把无关审查项提升为所有任务的前置条件。

达到任务验收即停止扩张，记录真实命令、结果、代码位置和剩余限制。接口存在、生产接线、默认启用、CI 通过、真实任务质量、供应商降本是不同事实，不以一种替代另一种。

不为满足文档而杜撰测试、完成率、CI 或费用；不只提交报告冒充功能完成。未获授权不创建 release/tag，不改写冻结证据。算法或产品范围变更依当前任务决定，不能从旧提案自动扩展。
