# Package 优化最终集成验收

本计划已完成，实际结果与限制见 [最终回执](FINAL_ACCEPTANCE_2026-09-20.md)。

2026-09-20，接续用户“继续，完成整个优化任务”。这是新开的零付费本地验证窗口，
不延长或重置 v2/v3 的旧 campaign，不覆盖任何已归档证据。

本次完成条件：

1. Runtime 取消保全的半批失败动态验证：第一条 observation 成功、第二条失败后
   围栏生效，无成功取消终态、无重复 ingest 或效果重放；覆盖两种公共取消入口。
2. 进程启动异常的所有当前测试控制器调用方接住已创建进程与清理事实；
   不因构造函数未返回而丢弃 owned process，不把清理失败写成 no process。
3. 新增 Python 回归接入既有 CI，覆盖 Windows，兼容的测试也在 Ubuntu 执行。
   本机运行与 workflow 接线是两种事实，不冒充远端 CI 已通过。
4. 最终工作树完成 workspace build/test/clippy/fmt、文档结构门以及公共客户端
   的既有 .NET 构建和测试；失败先定位、修复并重跑必要目标，不抹掉首次失败。
5. 新目录、新基线独立验收后，最终 helper/load/controller 源码冻结，运行完整
   1800 秒负载窗口（4 worker 与 GC、两次真实进程死亡）、当前 host 的连续旅程，
   最后停止所有 writer、重开数据库、核对所有历史回执及只读 auditor。
6. 最终回执绑定实际源码/二进制/测试命令，保留旧回执和模型原稿未验收事实。

负载准备应用沿用明确标为 assisted 的源码；host 使用本地合成供应商。
新窗口的模型决策、供应商 attempt 和付费估算上限均为 0。
这次交付是现有可复现缺陷的代码与验收闭环；不将供应商自主质量、无限规模、
恶意并发文件替换或价格/布局 A/B 等未声明目标扩展为完成条件。

原范围的代码和验证完成后停止扩张。共享工作树既有内容保留；提交/推送不在
此本地验收窗口内，远端 CI 结果只有真实运行后才能更新。
