## 验证分层

- **真实公共 host 流程**：4 个独立进程保持同一 TaskId；错误 TaskId 被拒，
  运行中纠正入队且满队拒绝；可见畸形模型响应失败后冷恢复保留 2876 字节指令；
  取消确认约 16 ms，只有一个对应取消终态，迟到文本没有进入后续请求或助手消息。
  [回执](evidence/host-verified.json)。这是本地合成供应商、真实 host 协议的证据。
- **组件回归**：45 项 Rust 定向测试通过，另 1 项诊断测试保持 ignored。
  包括 occupied GC＋in-flight prepare＋失败/取消/冷恢复、真实 SimpleContextEngine
  压缩取消、冷正文消费、权限过期、迟到用量结算及 effect 恢复围栏。
  命令与计数在总回执中；不把组件结果拼接成新的综合流程。
- **最终应用**：公共测试 2/2、模型自写测试 16/16 通过；独立检查仍失败。
  两个求解反例、租户隔离、损坏源字节拒绝、两处真实 exit 71 安装恢复、
  真实 exit 72 迁移恢复、未知未来数据库版本无修改拒绝通过。
  旧回执重放和 worker 失败，应用 README/DESIGN/RECOVERY/RESULT 均未交付。
  [应用测试](evidence/final-app-tests.json)、[独立检查](evidence/final-independent.json)。
- **未执行**：90 分钟负载及其中两次 worker 死亡、新 public-host 流程中
  部分工具批次取消＋权限撤销组合、伪造 PASS 文本注入、供应商布局 A/B 费用对照。

验收器原本把 stub 的 NotImplementedError 当作成功拒绝损坏文件，已增加有效安装
正对照及具体拒绝类型检查；原始 `superseded-initial-oracle.json` 中那一项 PASS
无效。增强后的验收器重新校准，确实拒绝损坏 blob、修改指针和缺失回执。
早期 future-schema 探针的 stub 拒绝同样不作有效证据，最终检查要求 ValueError
且数据库逐字节保持。
