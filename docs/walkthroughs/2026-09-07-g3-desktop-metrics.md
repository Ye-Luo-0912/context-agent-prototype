# 2026-09-07 G3 桌面工作台资源记录（首次采样）

范围：`apps/Agent.Desktop`（Avalonia 11.3.20，net10.0，Windows 11 x64，调试构建）。
本文只记录测过的事实；没测的指标一律 `NOT_RUN`，不写成结论。

## 已测

| 指标 | 方法 | 结果 |
|---|---|---|
| 空闲全进程工作集（仅桌面进程，无宿主连接） | 启动后 `Get-Process WorkingSet64` 采样 6 次 × 1s | 首样 222.5 MB → 末样 231.5 MB（~9 MB 抖动，.NET 运行时基线占主导） |
| 启动存活 | 启动 6 秒后进程仍存活、窗口可初始化 | 通过（G1 冒烟与本次一致） |
| 有界保留 | 代码内建：任务列表渲染上限 200 条、输出尾部上限 400 行、通知队列 1024 条（满则置 `NotificationsDropped`，不阻塞读循环） | 代码事实，未做大规模注入测试 |

## NOT_RUN（没有环境/前提，不写结论）

- 长会话内存斜率（需要真实 provider 的长任务；本环境无凭据，真实 provider live 记录为 `NOT_RUN`）。
- 输出时 CPU/分配（需要流式 delta 打到真实 UI；事件 wire 契约随 P2 类型化事件落地后可测）。
- 大 diff 响应（需要 diff/工件按需读取路由；路由未定义，不可测）。
- 与 TUI/WebView 方案的对照（不以"原生必然最省"为由写任何对比结论）。
- AOT/裁剪兼容性（工单明确不作为首窗前置，未做）。

## 边界声明

单一环境（开发机 Windows 11、调试构建）的一次采样不构成性能结论，更不构成
「Avalonia 比 WebView 省」的证据。测量的用途是给 G3 后续建立基线，采样脚本
（PowerShell `WorkingSet64` 循环）可直接重跑对比。
